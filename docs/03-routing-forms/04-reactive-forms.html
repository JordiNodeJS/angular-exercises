04 · Reactive forms: el formulario como modelo

El estado del formulario vive en TypeScript, tipado y testeable. La plantilla solo conecta inputs con ese modelo.

  • Proyecto: ch03-04-reactive-forms
  • Ruta: chapters/03-routing-forms/04-reactive-forms
  • Requiere: 01-signals
Objetivo de la clase

FormGroup, FormControl y validadores, con formularios tipados. Nota importante: en Angular 22 los formularios nuevos deberían usar Signal Forms.

1. Declarar el formulario

import { Component, inject } from '@angular/core';
import { FormControl, FormGroup, ReactiveFormsModule, Validators } from '@angular/forms';

@Component({
  imports: [ReactiveFormsModule],
  selector: 'app-registro',
  templateUrl: './registro.html',
})
export class Registro {
  private readonly api = inject(UsuariosService);

  protected readonly form = new FormGroup({
    nombre: new FormControl('', {
      nonNullable: true,
      validators: [Validators.required, Validators.minLength(3)],
    }),
    email: new FormControl('', {
      nonNullable: true,
      validators: [Validators.required, Validators.email],
    }),
    edad: new FormControl<number | null>(null),
  });

  protected enviar(): void {
    if (this.form.invalid) {
      this.form.markAllAsTouched();
      return;
    }
    this.api.crear(this.form.getRawValue());
  }
}

nonNullable: true hace que el control nunca valga null: se empieza en '' y reset() vuelve a ''. Sin eso, TypeScript te obliga a tratar null en cada lectura.

2. Conectar la plantilla

<form [formGroup]="form" (ngSubmit)="enviar()">
  <label>
    Nombre
    <input formControlName="nombre" />
  </label>

  @if (form.controls.nombre.invalid && form.controls.nombre.touched) {
    @if (form.controls.nombre.hasError('required')) {
      <p class="error">El nombre es obligatorio.</p>
    } @else if (form.controls.nombre.hasError('minlength')) {
      <p class="error">Como mínimo 3 caracteres.</p>
    }
  }

  <button type="submit" [disabled]="form.invalid">Registrar</button>
</form>

formControlName ata por nombre al FormGroup. Si el nombre no existe, falla en runtime, no en el build.

3. Validadores

Validador Comprueba
required No vacío (incluye null).
email Forma de email, no que exista.
minLength / maxLength Longitud del string.
pattern Regex. Última opción: el mensaje de error es peor. 
function sinEspacios(control: AbstractControl): ValidationErrors | null {
  const valor = control.value as string;
  return valor.includes(' ') ? { sinEspacios: true } : null;
}

El validador devuelve null si todo va bien, o un objeto de errores. Devuelve { campoInvalido: true }, no el booleano false: un false también cuenta como válido y esconde el bug.

4. Reaccionar a cambios

protected readonly email = toSignal(
  this.form.controls.email.valueChanges,
  { initialValue: this.form.controls.email.value },
);

valueChanges es un Observable. Como en el resto del repo, se convierte a signal en el borde con toSignal(); nada de suscripciones sueltas en la plantilla.

5. Signal Forms en Angular 22

@angular/forms/signals construye el formulario a partir de un signal y expone la validación como un schema. Convive con Reactive Forms, pero es la dirección recomendada para código nuevo: 

import { form, required, email } from '@angular/forms/signals';

Este ejercicio se hace con Reactive Forms porque es lo que pide el roadmap y porque el ecosistema está lleno de él. Cuando acabes, lee la guía de Signal Forms y compara: menos imports, sin formControlName y validación declarativa.

6. Ejercicio

  1. Crea un formulario de registro con nombre, email y edad, todos tipados y con nonNullable donde tenga sentido.
  2. Muestra el error solo cuando el campo está touched e invalid.
  3. Añade un validador propio que rechace espacios en el nombre y pruébalo en consola.
  4. Deshabilita el botón con [disabled]="form.invalid" y explica por qué también validas en enviar().
  5. Convierte valueChanges del email a signal y muestra un resumen en vivo.

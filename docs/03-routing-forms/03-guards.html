03 · Guards: decidir si se entra

Funciones, no clases. Devuelven true, false o una redirección, y se ejecutan en el momento de la navegación.

  • Proyecto: ch03-03-guards
  • Ruta: chapters/03-routing-forms/03-guards
  • Requiere: 03-01-router
Objetivo de la clase

CanActivateFn y CanMatchFn de autenticación, más un guard de datos para evitar perder un formulario a medio rellenar.

1. Un guard es una función

import { inject } from '@angular/core';
import { CanActivateFn, Router } from '@angular/router';

export const authGuard: CanActivateFn = () => {
  const sesion = inject(SesionService);
  const router = inject(Router);

  return sesion.estaLogueado() ? true : router.createUrlTree(['/login']);
};
{
  path: 'admin',
  canActivate: [authGuard],
  loadComponent: () => import('./admin/admin').then((m) => m.Admin),
}

Devolver un UrlTree es mejor que router.navigate() + false: el router cancela la navegación original y aplica la redirección en una sola operación.

2. Cuándo usar cada uno

Guard Se ejecuta… Uso típico
canActivate Al entrar en la ruta. Estás logueado.
canMatch Antes de cargar el chunk. La ruta ni existe para quien no tiene permiso.
canDeactivate Al salir. Hay cambios sin guardar.
resolve Antes de activar. Los datos están listos al pintar.

Con canMatch el bundle ni se descarga: el usuario sin permiso nunca recibe el código del área privada. Es la opción más segura para rutas lazy.

3. Guard de datos

export const sinCambiosGuard: CanDeactivateFn<Editor> = (componente) =>
  componente.tieneCambios() ? confirm('Hay cambios sin guardar. ¿Salir?') : true;
{
  path: 'editor',
  component: Editor,
  canDeactivate: [sinCambiosGuard],
}

confirm() es aceptable en un ejercicio; en producción se sustituye por un diálogo propio que devuelva un Promise<boolean>. El guard admite también Observable<boolean>.

4. Datos resueltos antes de entrar

export const productoResolver: ResolveFn<Producto> = (ruta) =>
  inject(ProductosService).detalle(ruta.paramMap.get('id')!);

{
  path: 'productos/:id',
  component: ProductoDetalle,
  resolve: { producto: productoResolver },
}

Con withComponentInputBinding() el resolver llega como input y el componente se pinta ya con datos, sin estado cargando.

Un guard no es seguridad. Todo lo que decide en el navegador se puede saltar: el backend tiene que validar permisos igual. El guard es UX y organización de rutas.

5. Ejercicio

  1. Crea SesionService con un signal estaLogueado y un botón para entrar y salir.
  2. Protege /admin con authGuard. Sin sesión debe redirigir a /login.
  3. Cambia el guard a canMatch y comprueba en Network que el chunk de admin no se descarga sin sesión.
  4. Añade un formulario con canDeactivate: si hay cambios, pide confirmación antes de salir.
  5. Añade un resolve a una ruta de detalle y elimina el estado de carga del componente.

Checklist de cierre

  • Build y prettier limpios.
  • Los guards son funciones con inject(), no clases.
  • La redirección se hace devolviendo UrlTree.
  • Sabes explicar por qué el guard no sustituye la validación del backend.

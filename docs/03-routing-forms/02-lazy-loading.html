02 · Lazy loading: cargar cuando se pisa

Partir el bundle por rutas. El usuario descarga lo que visita, no la app entera, y el build te lo dice con chunks separados.

  • Proyecto: ch03-02-lazy-loading
  • Ruta: chapters/03-routing-forms/02-lazy-loading
  • Requiere: 03-01-router
Objetivo de la clase

loadComponent y loadChildren, más la diferencia con component. Sabrás leer en el build qué se ha diferido y qué no.

1. Eager vs lazy

// eager: entra en el bundle inicial
{ path: 'inicio', component: Inicio }

// lazy: se descarga al navegar
{ path: 'admin', loadComponent: () => import('./admin/admin').then((m) => m.Admin) }

Con component el código viaja en el main.js. Con loadComponent el compilador crea un chunk aparte y lo pide en la primera navegación.

2. loadComponent

{
  path: 'admin',
  loadComponent: () => import('./admin/admin').then((m) => m.Admin),
}

Si el componente tiene export default, el then sobra:

// admin.ts
export default class Admin { /* ... */ }

// routes
{ path: 'admin', loadComponent: () => import('./admin/admin') }

Una ruta lazy no aporta nada si el componente es diminuto o se visita siempre al arrancar: añades una petición de red a cambio de nada.

3. loadChildren

Para diferir un bloque entero con sus rutas hijas:

// tienda/tienda.routes.ts
import { Routes } from '@angular/router';

export const routes: Routes = [
  { path: '', component: Tienda },
  { path: ':id', component: Producto },
];
// app.routes.ts
{
  path: 'tienda',
  loadChildren: () => import('./tienda/tienda.routes').then((m) => m.routes),
}

Ventaja frente a loadComponent: el chunk incluye todo lo que comparten esas rutas hijas, y los providers de la ruta se crean ahí (otro inyector, otra instancia de los servicios que declare).

4. Comprobarlo en el build

ng build ch03-02-lazy-loading
Initial chunk files | Names         |  Raw size
main-XXXX.js        | main          | 190.33 kB
styles-XXXX.css     | styles        |   0 bytes

Lazy chunk files    | Names         |  Raw size
chunk-XXXX.js       | admin         |  12.10 kB
chunk-YYYY.js       | tienda-routes |  25.40 kB

Si la ruta lazy no aparece como Lazy chunk, el import ha quedado estático: revisa que no haya un import normal del componente en otro fichero, que lo arrastraría al bundle inicial.

Un import estático del componente diferido en cualquier sitio (aunque sea solo para un tipo) rompe el lazy loading. Para tipos, usa import type.

5. Precarga (opcional)

providers: [provideRouter(routes, withPreloading(PreloadAllModules))];

Mantiene el bundle inicial pequeño, pero descarga el resto en segundo plano cuando la app está ociosa. Útil cuando las rutas se visitan casi siempre.

6. Ejercicio

  1. Convierte una ruta existente a loadComponent y compara el build antes y después.
  2. Crea una sección tienda con dos rutas hijas y loadChildren.
  3. Comprueba en la pestaña Network que el chunk se pide solo al entrar en la sección.
  4. Rompe el lazy loading con un import estático del componente diferido y explica qué cambia en el build.
  5. Añade withPreloading(PreloadAllModules) y observa cuándo se descarga ahora.

Checklist de cierre

  • El build muestra al menos un Lazy chunk.
  • Build y prettier limpios.
  • Sin imports estáticos de los componentes diferidos.
  • Sabes explicar qué providers cambian de alcance con loadChildren.

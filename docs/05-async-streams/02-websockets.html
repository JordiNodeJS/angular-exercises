02 · WebSockets: el servidor manda, el stream recibe

HTTP es petición y respuesta. Un socket es una tubería abierta: el servidor empuja cuando quiere. Eso encaja con un Subject, no con un signal.

  • Proyecto: ch05-02-websockets
  • Ruta: chapters/05-async-streams/02-websockets
  • Requiere: 02-04-rxjs

Arranca: ng serve ch05-02-websockets localhost:4200

Objetivo de la clase

Subject, BehaviorSubject, scan y reconexión con backoff. Y lo más importante: cerrar el socket cuando el componente desaparece.

1. Qué cambia respecto a HTTP

HTTP WebSocket
Empiezas tú. Empieza el servidor cuando hay novedades.
Una respuesta por petición. Mensajes indefinidos sobre la misma conexión.
HttpClient resuelve la cancelación. La cancelación la pones tú: socket.close().

2. Subject y sus variantes

Un Subject es a la vez Observable y Observer: puedes subscribirte y también hacer next().

Tipo Qué recuerda Uso
Subject Nada. Eventos que solo importan a quien está conectado: mensajes de chat.
BehaviorSubject El último valor y uno inicial. Estado actual: conexión abierta o cerrada.
ReplaySubject(n) Los últimos n valores. Buffers cortos que un componente que llega tarde necesita.

3. Envolver el socket

import { Service, inject } from '@angular/core';
import { Observable, Subject } from 'rxjs';

export interface Mensaje {
  tipo: 'chat' | 'sistema';
  texto: string;
}

@Service()
export class ChatService {
  private readonly url = inject(API_URL);
  private readonly entrantes = new Subject<Mensaje>();
  private socket: WebSocket | null = null;

  readonly mensajes: Observable<Mensaje> = this.entrantes.asObservable();

  conectar(): void {
    this.socket = new WebSocket(this.url);

    this.socket.addEventListener('message', (evento) => {
      const data = JSON.parse((evento as MessageEvent).data) as Mensaje;
      this.entrantes.next(data);
    });

    this.socket.addEventListener('close', () => {
      this.socket = null;
      this.entrantes.complete();
    });
  }

  enviar(texto: string): void {
    this.socket?.send(JSON.stringify({ tipo: 'chat', texto } satisfies Mensaje));
  }

  cerrar(): void {
    this.socket?.close();
  }
}

asObservable() expone solo la parte de lectura: los componentes pueden suscribirse pero no hacer next(). El socket es del servicio.

4. Reconexión con backoff

El servidor se cae, la red cambia, el portátil duerme. Sin reconexión el chat se queda mudo. Se resuelve con un Observable que reintenta: 

import { Observable, retry, timer } from 'rxjs';

function conectar(url: string): Observable<Mensaje> {
  return new Observable<Mensaje>((suscriptor) => {
    const socket = new WebSocket(url);

    socket.addEventListener('message', (e) =>
      suscriptor.next(JSON.parse((e as MessageEvent).data) as Mensaje),
    );
    socket.addEventListener('close', () => suscriptor.complete());

    return () => socket.close();
  }).pipe(
    retry({
      count: 5,
      delay: (intento) => timer(Math.min(1000 * 2 ** intento, 30_000)),
    }),
  );
}

El delay exponencial evita ametrallar el servidor: 1 s, 2 s, 4 s, 8 s… con tope de 30 s. El return () => socket.close() es la limpieza: se ejecuta al desuscribirse o al cancelar.

5. Cerrar al salir

El socket no se cierra solo. Si el componente que lo abrió desaparece, alguien tiene que llamar a cerrar(): 

import { DestroyRef, inject } from '@angular/core';

export class Chat {
  private readonly chat = inject(ChatService);
  private readonly destroyRef = inject(DestroyRef);

  constructor() {
    this.chat.conectar();

    this.destroyRef.onDestroy(() => this.chat.cerrar());
  }
}

DestroyRef es la forma moderna de ngOnDestroy: se registra el callback y Angular lo ejecuta al destruir el componente. Si no lo haces, la conexión sigue abierta y el servidor envía mensajes que ya nadie lee.

Y si los mensajes se consumen con toSignal(), la desuscripción es automática; lo que no es automático es el socket.close().

Un socket abierto es una suscripción que no termina por sí sola. En una SPA con router, olvidar el close() acumula conexiones en cada navegación.

6. Ejercicio

  1. Crea un ChatService con Subject, conectar() y enviar().
  2. Pinta los mensajes con scan para ir acumulándolos en un signal.
  3. Añade un BehaviorSubject<boolean> de conexión y muestra «conectado» o «reconectando».
  4. Implementa la reconexión con retry y backoff exponencial. Comprueba que no satura la consola.
  5. Navega a otra ruta y vuelve: el socket anterior tiene que estar cerrado.

Checklist de cierre

  • Build y prettier limpios.
  • El socket se cierra al destruir el componente o el servicio.
  • La reconexión tiene backoff y un número máximo de intentos.
  • Ningún componente hace next() sobre el Subject del servicio.

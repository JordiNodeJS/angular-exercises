Capítulo 04 · Quality

02 · Lint y build de producción

Que lo que funciona en ng serve también funcione fuera. Presupuestos, formato, lint y un bundle que sabes leer.

  • Proyecto: ch04-02-build
  • Ruta: chapters/04-quality/02-build
  • Requiere: capítulo 03

Arranca: ng build ch04-02-build

Objetivo de la clase

ESLint + Prettier y ng build en modo producción. Aprender a leer el resumen de bundles y a justificar (o no) una dependencia nueva.

1. Prettier

Ya está en el workspace y no hace falta reinstalarlo. La configuración vive en .prettierrc en la raíz. 

pnpm exec prettier --check "chapters/04-quality/02-build/**/*.{ts,html,css}"
pnpm exec prettier --write "chapters/04-quality/02-build/**/*.{ts,html,css}"

--check es lo que se usa en verificación: no toca ficheros, solo dice si están formateados. El formato no se negocia en review.

2. ESLint

ESLint no está instalado en este workspace. Instalarlo es una dependencia nueva y requiere pedirlo antes; la clase lo explica, el repo no lo añade por su cuenta. 

ng add @angular/eslint
  • Se ejecuta con ng lint.
  • Las reglas de Angular detectan plantillas mal escritas y APIs deprecadas.
  • Un warning no es un error: si lo dejas, deja escrito por qué.

3. Build de producción

ng build ch04-02-build
Initial chunk files | Names         |  Raw size | Estimated transfer size
main-7IMRXGG7.js    | main          | 190.33 kB |                51.90 kB
styles-5INURTSO.css | styles        |   0 bytes |                 0 bytes

defaultConfiguration es production: minificado, con outputHashing: 'all' y sin source maps. El build de desarrollo es otro perfil: 

ng build ch04-02-build --configuration development
Opción Qué cambia
outputHashing Nombre con hash: cache busting. Necesario en producción.
optimization Minificado y tree-shaking.
sourceMap Solo en desarrollo. En producción expone el código fuente.
budgets Umbrales de tamaño: warning y error.

4. Presupuestos

"budgets": [
  { "type": "initial", "maximumWarning": "500kB", "maximumError": "1MB" },
  { "type": "anyComponentStyle", "maximumWarning": "4kB", "maximumError": "8kB" }
]

Un budget warning no rompe el build, un budget error sí. Subir el umbral para callar el aviso es una decisión de producto: primero mira qué ha crecido y por qué.

5. Antes de dar por cerrado un ejercicio

ng build ch04-02-build
pnpm exec prettier --check "chapters/04-quality/02-build/**/*.{ts,html,css}"

Si el ejercicio toca routing o formularios, además ng serve ch04-02-build tiene que arrancar sin errores en consola.

6. Ejercicio

  1. Ejecuta el build de producción y el de desarrollo del mismo proyecto. Anota la diferencia de tamaño y por qué.
  2. Añade 3 componentes con estilos y mira cómo se mueve anyComponentStyle.
  3. Crea un componente con un CSS de 6 kB y observa el warning de presupuesto. Baja el umbral y provoca el error.
  4. Pasa prettier --check, rompe el formato a propósito y arréglalo con --write.
  5. Justifica por escrito si merece la pena añadir ESLint al workspace o no. No lo instales sin decidirlo.

Checklist de cierre

  • Build de producción sin warnings nuevos.
  • Prettier limpio en las rutas del ejercicio.
  • Sabes qué configuración aplica ng build por defecto y cómo cambiarla.
  • No has añadido dependencias sin pedirlo.

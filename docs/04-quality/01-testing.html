01 · Testing: componentes y servicios

Probar comportamiento, no implementación. Un test que se rompe al renombrar una variable privada está mal escrito.

  • Proyecto: ch04-01-testing
  • Ruta: chapters/04-quality/01-testing
  • Requiere: capítulo 02

Arranca: ng test ch04-01-testing

Objetivo de la clase

TestBed, tests de componentes y de servicios, y peticiones HTTP con HttpTestingController. Es el único ejercicio que se genera sin --minimal.

1. Generar el ejercicio con tests

ng generate application ch04-01-testing \
  --project-root=chapters/04-quality/01-testing \
  --style=css

Sin --minimal. Es la excepción del repo: aquí los tests son el ejercicio, no ruido. El runner por defecto del proyecto es el que configure el CLI; comprueba el package.json y el target test antes de empezar.

2. Un servicio puro

describe('CarritoService', () => {
  let servicio: CarritoService;

  beforeEach(() => {
    TestBed.configureTestingModule({});
    servicio = TestBed.inject(CarritoService);
  });

  it('empieza vacío', () => {
    expect(servicio.lineas()).toEqual([]);
    expect(servicio.total()).toBe(0);
  });

  it('suma el total al añadir', () => {
    servicio.anadir({ id: 1, precio: 10, cantidad: 2 });
    expect(servicio.total()).toBe(20);
  });
});

TestBed.inject() da la misma instancia que usaría la app: no hace falta construirla a mano.

3. Un componente

describe('Contador', () => {
  beforeEach(async () => {
    await TestBed.configureTestingModule({ imports: [Contador] }).compileComponents();
  });

  it('incrementa al pulsar', async () => {
    const fixture = TestBed.createComponent(Contador);
    fixture.detectChanges();

    const boton: HTMLButtonElement = fixture.nativeElement.querySelector('button');
    boton.click();
    await fixture.whenStable();
    fixture.detectChanges();

    expect(fixture.nativeElement.querySelector('p').textContent).toContain('1');
  });
});
  • createComponent no renderiza; hace falta detectChanges().
  • En apps zoneless, espera con await fixture.whenStable() antes de leer el DOM.
  • Si el componente usa input(), asígnalo con fixture.componentRef.setInput('nombre', 'Ada') antes del primer detectChanges().

4. HTTP con HttpTestingController

import { provideHttpClient } from '@angular/common/http';
import { provideHttpClientTesting, HttpTestingController } from '@angular/common/http/testing';

describe('UsuariosService', () => {
  beforeEach(() => {
    TestBed.configureTestingModule({
      providers: [provideHttpClient(), provideHttpClientTesting()],
    });
  });

  it('lista usuarios', () => {
    const servicio = TestBed.inject(UsuariosService);
    const http = TestBed.inject(HttpTestingController);

    let resultado: Usuario[] = [];
    servicio.listar().subscribe((usuarios) => (resultado = usuarios));

    const peticion = http.expectOne('/api/usuarios');
    expect(peticion.request.method).toBe('GET');
    peticion.flush([{ id: 1, nombre: 'Ada', email: 'ada@ejemplo.dev' }]);

    expect(resultado.length).toBe(1);
    http.verify();
  });
});

http.verify() falla si quedó alguna petición sin responder. Es la red de seguridad contra tests que «pasan» sin comprobar nada.

5. Qué probar y qué no

Sí No
Lógica de negocio del servicio. Que Angular renderiza un @if.
Validadores y estados de error. Detalles de implementación (métodos privados).
Que un clic produce el efecto esperado. Que un componente llama a un método concreto.
Contratos HTTP (URL, método, cuerpo). La respuesta real de un backend.

6. Ejercicio

  1. Genera el ejercicio sin --minimal y ejecuta los tests que trae por defecto. Deben pasar antes de tocar nada.
  2. Escribe tres tests de CarritoService: vacío, añadir y total.
  3. Escribe un test de componente que pulse un botón y compruebe el DOM.
  4. Escribe un test de UsuariosService con HttpTestingController, incluido el caso de error 500.
  5. Rompe a propósito la lógica del servicio y comprueba que el test falla. Un test que no puede fallar no vale.

Checklist de cierre

  • ng test ch04-01-testing en verde.
  • Build y prettier limpios.
  • Ningún setTimeout en un test: esperas con whenStable.
  • Has visto un test fallar a propósito y volver a verde.

Capítulo 01 · Fundamentals

01 · Hello world: CLI y estructura

Entender qué genera el CLI, por dónde arranca la app y qué hace cada fichero. Nada de componentes nuevos todavía: primero el esqueleto.

  • Proyecto: ch01-01-hello-world
  • Ruta: chapters/01-fundamentals/01-hello-world
  • Nivel: arranque
Objetivo de la clase

pnpm, ng serve y la anatomía de main.ts y app.config.ts. Al terminar sabes qué fichero tocar para cambiar el arranque de una app Angular standalone.

1. Un workspace, una app por ejercicio

El repo no usa ng new por ejercicio. Hay un único workspace con un solo node_modules y un angular.json que registra cada app: 

angular-exercises/
├── angular.json          ← fuente de verdad de los proyectos
├── package.json          ← una sola instalación
├── pnpm-workspace.yaml
└── chapters/
    └── 01-fundamentals/
        └── 01-hello-world/   ← project-root de la app

Para añadir un ejercicio nuevo (nunca dentro de uno existente):

pnpm exec ng generate application ch02-03-http \
  --project-root=chapters/02-state-data/03-http \
  --style=css --minimal
Flag Para qué
--project-root Coloca los ficheros en chapters/<capítulo>/<ejercicio>.
--style=css Sin preprocesadores. CSS plano siempre.
--minimal Sin tests. Solo se omite en el capítulo de testing.

Si el comando acaba con Project name already exists pero los ficheros están creados, es la segunda pasada del CLI después de instalar dependencias. Comprueba el build antes de tocar nada.

2. Anatomía del arranque

Angular 22 arranca con bootstrapApplication. No hay AppModule: la configuración es un objeto ApplicationConfig con providers.

src/main.ts — el punto de entrada

import { bootstrapApplication } from '@angular/platform-browser';
import { appConfig } from './app/app.config';
import { App } from './app/app';

bootstrapApplication(App, appConfig).catch((err) => console.error(err));

Monta el componente raíz y aplica la configuración. Es el único sitio que el CLI usa como browser en angular.json. Si algún día sobra el .catch, los errores de arranque desaparecen sin traza: no lo quites.

src/app/app.config.ts — los providers globales

import { ApplicationConfig, provideBrowserGlobalErrorListeners } from '@angular/core';
import { provideRouter } from '@angular/router';
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [provideBrowserGlobalErrorListeners(), provideRouter(routes)],
};

Aquí se enchufa todo lo que es global: router, HTTP, hidratación, interceptores. Cada provide* es una función que devuelve providers; se componen en array.

src/app/app.ts — el componente raíz

import { Component, signal } from '@angular/core';
import { RouterOutlet } from '@angular/router';

@Component({
  imports: [RouterOutlet],
  selector: 'app-root',
  styles: [],
  template: `
    <h1>{{ title() }}</h1>

    <router-outlet />
  `,
})
export class App {
  protected readonly title = signal('Hello world');
}

Fíjate en tres cosas que en Angular 22 son el default y por eso no aparecen: standalone: true, changeDetection: OnPush y standalone en el import del componente. Escribirlos es ruido.

src/index.html — el host

<body>
  <app-root></app-root>
</body>

El selector del componente raíz (app-root) tiene que coincidir con esta etiqueta. Si lo renombras en app.ts y no aquí, la app se queda en blanco sin error de compilación.

3. Sin zone.js

Este workspace no instala zone.js y no hay provideZoneChangeDetection() en la configuración: la app es zoneless. La detección de cambios se dispara con signals, eventos del template y APIs de Angular, no parcheando APIs del navegador.

Consecuencia práctica: el estado que quieras ver en pantalla debe ser un signal() (o un valor que Angular lea durante el render). Una propiedad normal mutada desde un callback externo puede no refrescar la vista.

4. Ejercicio

  1. Sirve la app: pnpm exec ng serve ch01-01-hello-world y abre http://localhost:4200.
  2. Cambia el texto del signal a Hola Angular con el servidor corriendo. Debe recargarse solo (HMR). Si no lo hace, mira la consola del dev-server.
  3. Añade un segundo signal (subtitulo) y muéstralo en un <p> con interpolación.
  4. Renombra el selector a app-raiz en app.ts y olvídate del index.html. ¿Qué ves? Arréglalo en un solo sitio y explica cuál era el problema.
  5. Quita RouterOutlet de imports dejando <router-outlet /> en la plantilla. Lee el error del compilador entero: es el patrón de error que verás mil veces (NG8001).
  6. Ejecuta pnpm exec ng build ch01-01-hello-world y localiza el bundle en dist/ch01-01-hello-world.

Checklist de cierre

  • pnpm exec ng build ch01-01-hello-world termina sin errores.
  • pnpm exec prettier --check "chapters/01-fundamentals/01-hello-world/**/*.{ts,html,css}" limpio.
  • Sabes decir en qué fichero se añade un provider global y en cuál se cambia el componente raíz.
  • No has añadido dependencias ni tocado otros proyectos.

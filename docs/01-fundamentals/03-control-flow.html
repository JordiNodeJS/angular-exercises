03 · Control flow: @if, @for, @switch

El control de flujo nativo del template sustituye a las directivas estructurales. Es sintaxis de bloque, no atributos: se ve qué pertenece a qué sin leer *ngIf.

  • Proyecto: ch01-03-control-flow
  • Ruta: chapters/01-fundamentals/03-control-flow
  • Requiere: 02-templates
Objetivo de la clase

@if, @for y @switch, con sus variantes @else, @empty y track. Y por qué *ngIf / *ngFor están fuera del repo.

1. @if

@if (usuario(); as u) {
  <p>Hola, {{ u.nombre }}</p>
} @else if (cargando()) {
  <p>Cargando…</p>
} @else {
  <p>No hay sesión.</p>
}

as da nombre al valor cuando la condición es verdadera: es la forma limpia de evitar usuario()!.nombre repetido.

@if crea y destruye el DOM. Si el bloque contiene un componente, se destruye de verdad (con su estado y sus suscripciones). No es [hidden].

2. @for

track es obligatorio:

@for (tarea of tareas(); track tarea.id) {
  <li>{{ $index + 1 }}. {{ tarea.titulo }}</li>
} @empty {
  <li>No hay tareas.</li>
}

Variables implícitas disponibles dentro del bloque:

Variable Valor
$index Posición, desde 0.
$first / $last Booleano para el primer y último elemento.
$even / $odd Paridad del índice.
$count Total de elementos.

track decide qué se reutiliza al cambiar la lista. Usa una clave estable (item.id), nunca $index si la lista se reordena o se filtra: se reutilizan nodos con el estado equivocado.

3. @switch

@switch (estado()) {
  @case ('cargando') {
    <app-spinner />
  }
  @case ('error') {
    <p>Algo falló.</p>
  }
  @default {
    <app-lista />
  }
}

Compara con ===. No hay fallthrough: al acabar un @case se sale del bloque. Para dos estados que comparten vista, une la condición antes de llegar al template (computed()) en vez de duplicar @case.

4. Lo que ya no se escribe

Antes Ahora
*ngIf @if
*ngFor + trackBy @for + track
*ngSwitch @switch
ng-container con directivas @if / @for directamente

El motivo no es estético: los bloques nativos son más rápidos, no necesitan importar NgIf ni NgFor y el compilador los valida mejor. Además, las directivas antiguas obligan a importar piezas sueltas en cada componente.

5. Ejercicio

  1. Monta una lista de tareas con un signal de array y píntala con @for + @empty. Cada tarea con id, titulo y hecha.
  2. Añade un computed() con el contador de pendientes y un @if que muestre «Todo hecho» cuando no queden.
  3. Añade un filtro (todas / pendientes / hechas) y resuélvelo con @switch en la cabecera y @for en la lista.
  4. Marca visualmente la primera y la última con $first y $last.
  5. Cambia track tarea.id por track $index, borra la primera tarea y explica qué pasa con las que ya estaban marcadas.

Checklist de cierre

  • Build y prettier limpios.
  • Ningún *ngIf, *ngFor ni *ngSwitch en el repo.
  • Todos los @for tienen track con clave estable.
  • El estado vacío está cubierto con @empty, no con un @if aparte.

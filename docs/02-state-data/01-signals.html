01 · Signals: el estado por defecto

Un signal es un valor con notificación de cambio. Angular lo lee durante el render y sabe exactamente qué vista depende de él. Sin zone.js y sin suscripciones.

  • Proyecto: ch02-01-signals
  • Ruta: chapters/02-state-data/01-signals
  • Requiere: capítulo 01

Arranca: ng serve ch02-01-signals localhost:4200

Objetivo de la clase

signal, computed y effect, más linkedSignal y untracked cuando el caso lo pide. Regla del repo: deriva con computed(), nunca con mutate.

1. signal()

import { signal } from '@angular/core';

readonly contador = signal(0);

incrementar(): void {
  this.contador.update((n) => n + 1);   // depende del valor anterior
}

reiniciar(): void {
  this.contador.set(0);                   // valor absoluto
}

Un signal se lee con paréntesis. update recibe una función pura: si el valor nuevo es igual al anterior (Object.is), no hay notificación. 

// objetos y arrays: siempre inmutables
readonly tareas = signal<Tarea[]>([]);

anadir(tarea: Tarea): void {
  this.tareas.update((lista) => [...lista, tarea]);
}

.mutate() está deprecado y este repo lo prohíbe: mutar el array no cambia la referencia y los @for / computed no se enteran.

2. computed(): estado derivado

readonly tareas = signal<Tarea[]>([]);
readonly pendientes = computed(() => this.tareas().filter((t) => !t.hecha).length);
readonly progreso = computed(() => {
  const total = this.tareas().length;
  return total === 0 ? 0 : Math.round(((total - this.pendientes()) / total) * 100);
});

Es de solo lectura, se memoiza y se recalcula cuando cambia alguna de sus fuentes. Es perezoso: si nadie lo lee, no se calcula.

Si te encuentras un effect() que escribe otro signal a partir de otro, casi siempre es un computed() mal escrito.

3. effect(): efectos secundarios

import { effect } from '@angular/core';

constructor() {
  effect((onCleanup) => {
    const id = this.seleccionadoId();
    if (!id) return;

    const sub = this.api.suscribirse(id);
    onCleanup(() => sub.unsubscribe());
  });
}
Sí No
Logging, analytics, localStorage, sincronizar con algo externo. Calcular estado derivado.
Limpiar con onCleanup. Cambiar signals que otros effects leen (bucles).

Corre después del render, en el contexto de inyección. Si necesitas ejecutarlo una vez al arrancar, probablemente quieras afterNextRender().

4. linkedSignal()

Un signal escribible que se reinicia cuando cambia su fuente, pero que el usuario puede sobrescribir mientras tanto. El caso clásico: selección por defecto de una lista. 

readonly ciudades = signal(['Madrid', 'Lisboa', 'Roma']);
readonly ciudad = linkedSignal(() => this.ciudades()[0]);

// el usuario puede cambiarla
this.ciudad.set('Roma');
// si `ciudades` cambia, `ciudad` vuelve al primer elemento

Con computed() no podrías escribir; con signal() + effect() acabarías en un bucle. linkedSignal existe exactamente para esto.

5. untracked()

readonly resumen = computed(() => {
  const filtro = this.filtro();          // sí: dependencia
  const total = untracked(() => this.tareas().length); // no: solo lectura puntual
  return `${filtro}: ${total}`;
});

Lee un signal sin registrar la dependencia. Se usa cuando no quieres que el computed se recalcule por ese valor. Si dudas, no lo uses.

6. Ejercicio

  1. Modela un carrito: lineas como signal de array, total y unidades como computed().
  2. Implementa añadir, quitar y cambiar cantidad sin mutar: siempre set / update con arrays nuevos.
  3. Añade un effect() que guarde el carrito en localStorage y recupéralo al arrancar. ¿Dónde va la lectura inicial, en el signal o en el effect?
  4. Añade un selector de moneda con linkedSignal() para que la moneda elegida se mantenga mientras no cambie el país.
  5. Intenta escribir un computed desde otro y explica el error del compilador.

Checklist de cierre

  • Build y prettier limpios.
  • Ni un mutate; todo set / update.
  • Todo lo derivable es computed(); los effect() solo tocan el exterior.
  • El estado vive en el componente o en un servicio, no en variables sueltas.

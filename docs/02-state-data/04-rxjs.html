04 · RxJS: streams donde toca

RxJS sigue en Angular para eventos y cancelación. La regla del repo: un Observable se convierte en signal en el borde, y el componente no se suscribe a mano.

  • Proyecto: ch02-04-rxjs
  • Ruta: chapters/02-state-data/04-rxjs
  • Requiere: 02-03-http
Objetivo de la clase

Observable, map, switchMap, catchError y toSignal. Y saber cuándo no hace falta RxJS.

1. Observable, en una frase

Una colección de valores a lo largo del tiempo, con cancelación. Un Promise entrega un valor y termina; un Observable puede entregar muchos, ninguno o fallar, y se puede cancelar antes. 

import { Observable } from 'rxjs';

readonly teclas$: Observable<string> = fromEvent<KeyboardEvent>(document, 'keydown').pipe(
  map((e) => e.key),
);

El $ al final del nombre es convención, no sintaxis: avisa de que es un stream, no un valor.

2. Los operadores que se usan de verdad

Operador Para qué
map Transformar cada valor.
filter Descartar valores.
switchMap Cambiar a otro stream y cancelar el anterior. El de las búsquedas.
catchError Convertir un error en un valor o relanzarlo.
debounceTime + distinctUntilChanged Esperar a que el usuario pare de escribir y evitar repetidos.
tap Efecto lateral de depuración. Se quita antes de cerrar el ejercicio.

mergeMap no cancela, concatMap encola. Para peticiones disparadas por input del usuario, casi siempre quieres switchMap.

3. Búsqueda con switchMap

readonly resultados = toSignal(
  this.busqueda.valueChanges.pipe(
    debounceTime(300),
    distinctUntilChanged(),
    switchMap((texto) =>
      this.http.get<Resultado[]>('/api/buscar', { params: { q: texto } }).pipe(
        catchError(() => of([] as Resultado[])),
      ),
    ),
  ),
  { initialValue: [] as Resultado[] },
);

Cada tecla cancelaría la petición anterior si no hubiera debounceTime; switchMap se queda con la última respuesta y descarta las viejas que lleguen tarde.

4. toSignal(): el puente

import { toSignal } from '@angular/core/rxjs-interop';

readonly usuarios = toSignal(this.usuariosService.listar(), {
  initialValue: [] as Usuario[],
});
  • Se usa en campo de clase o en contexto de inyección.
  • Se desuscribe solo al destruir el componente.
  • Con initialValue no hay undefined en la plantilla.

El camino inverso es toObservable(), necesario cuando un operador tiene que reaccionar a un signal.

5. Suscripciones manuales: cuándo y cómo

Solo para efectos imperativos (un toast, una navegación al terminar). Siempre con limpieza: 

private readonly destroyRef = inject(DestroyRef);

constructor() {
  this.api.guardar(this.form.value).pipe(takeUntilDestroyed(this.destroyRef)).subscribe({
    next: () => this.toast.exito('Guardado'),
    error: () => this.toast.error('No se pudo guardar'),
  });
}

Un .subscribe() sin takeUntilDestroyed es una fuga de memoria y una escritura en un componente muerto. Es el error más común de esta clase.

6. Ejercicio

  1. Crea un buscador con FormControl o un signal + toObservable(). Aplica debounceTime, distinctUntilChanged y switchMap.
  2. Convierte el resultado a signal con toSignal() y pinta lista vacía, cargando y error.
  3. Cambia switchMap por mergeMap y provoca respuestas fuera de orden (latencia artificial). Explica qué se ve en pantalla y por qué.
  4. Añade un botón que dispare un guardado y gestione el resultado con takeUntilDestroyed.
  5. Elimina todos los .subscribe() que no sean imprescindibles. ¿Cuántos quedan y por qué?

Checklist de cierre

  • Build y prettier limpios.
  • Sin subscribe sueltos: o toSignal o takeUntilDestroyed.
  • La búsqueda cancela peticiones anteriores.
  • Ningún tap de depuración en el resultado final.
